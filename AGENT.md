# Правила работы агента в этом репозитории

## Ветка

**Ветка агента — `ai_agent`.**

Запись в рабочее дерево разрешена **только** в этой ветке. Любая правка файлов,
`git add`, `git commit`, создание и удаление файлов — только на `ai_agent`.

Правило проверяется **до** любой операции записи:

```sh
git rev-parse --abbrev-ref HEAD   # должно вернуть ai_agent
```

Если вернулось что-то другое — остановиться и не писать. Переключиться:

```sh
git checkout -b ai_agent          # ветки ещё нет
git checkout ai_agent             # ветка уже есть
```

Любые другие ветки трогать нельзя: там работает пользователь.

## Стиль правок

Правки должны быть **минимальной инвазией**.

1. **Комментарии в код не вносить.** Никаких `//`, `/* */`, `/** */`, в том числе
   «объясняющих» и «TODO». Готовые комментарии, которые уже есть в файлах,
   не трогать и не удалять — если правка требует их удаления, значит правка
   сделана неверно.

2. **Сохранять и соблюдать общий формат кода файла.** Стиль, отступы, порядок модификаторов, имена,
   порядок членов класса, расположение фигурных скобок, отсутствие/наличие
   пустых строк — всё как в исходном файле. Ориентир на `.clang-format`.
   Не переформатировать файл целиком, не менять отступы соседних строк,
   не «приводить к единому виду» то, что не является ошибкой.

3. **Функционал не терять.** Правка меняет только то, что является дефектом.
   Поведение, на которое нет жалобы, сохраняется буквально. Если исправление
   меняет наблюдаемое поведение — это отдельное решение, а не следствие
   чистки кода.

4. **Объём правки = объём дефекта.** Не рефакторить попутно, не удалять
   «просто неиспользуемый» код, не выносить глобалы из заголовков, не
   переписывать дублирующуюся логику на шаблоны, не переименовывать.
   Отдельные замечания по качеству — это список для человека, а не задача
   на молчаливое исправление.

Отдельно: если правка требует рефакторинга, удаления файла, изменения
структуры или новой зависимости — описать это в ответе и ждать решения.
Не делать.

## Проверка результата

Сборка обязательна после любой правки в `src/`:

```sh
"$USERPROFILE/.platformio/penv/Scripts/pio.exe" run -e esp32dev
```

Имя окружения брать из `platformio.ini`. Сейчас там только `[env:esp32dev]`.

`pio` в `PATH` отсутствует, нужен полный путь. Ожидается `SUCCESS`.

В конце успешной сборки `firmware.py` печатает отчёт о размере с эмодзи,
что роняет консоль cp1251 с `UnicodeEncodeError`. Это происходит **после**
успешной компиляции — на результат сборки не влияет, но код возврата
при этом ненулевой, так что ориентироваться нужно на строку `SUCCESS`,
а не на код выхода.

Отдельно: `.pio/` собирать заново не нужно, кеш инкрементальный.

## Работа с задачами

Если пользователь пишет «работаем над задачей <номер>», или близкое по смыслу (например, «работаем над задачей <номер>»):
   - проверить наличие файла с описанием задачи `ai_task/<номер>.md`;
   - если файл с описанием уже есть — продолжаем работу (читать/обновлять файл `ai_task/<номер>.md`);
   - если файла с описанием нет — создать его и начать работу (читать/обновлять файл `ai_task/<номер>.md`);
   - детальный ход(лог) работы, мысли и выводы по задаче записывать в файл `ai_task/<номер>.md` (обновлять по мере продвижения);
